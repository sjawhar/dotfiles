# scripts

Standalone utility scripts and small tools.

## Contents

Executables covering several areas:

- **OpenCode/Claude/omp sessions** — `agentbox` (`new [-e NAME[=VALUE]]… <repo>… -- <cmd>|sh|ls|doctor|rebuild|restart`: one Sysbox box per agent session holding a fresh jj workspace of each `~/src/<repo>`, working in the first; `-e` sets a variable in the box, since the caller's environment does not reach it; `omp` inside it is the same `shims/omp`, run under `agentbox-run.ts` so `agentbox restart` can relaunch it in place on the current pin and plugins; the box dies with the session, and its workspaces and knives claims go with it), `agentbox-run.ts` (the box's main process: omp's parent, relaunches it on SIGUSR1 — `agentbox restart` inside a box — and otherwise exits with it), `oc`, `oco`, `ompo` (omp under a named profile, billed only to that profile's `*_API_KEY_<NAME>` secrets; see `shims/omp`), `cld`, `claude-statusline` (Claude Code's status line, set in `.claude/settings.json`: a 10-cell bar of the context the next request carries, green under 50%, yellow under 80%, red above, e.g. `ctx ██▌░░░░░░░ 25% 250k/1M`, from the `context_window` Claude Code pipes in), `claude-session-repair.py`, `claude-transcript-times`, `sanitize-opencode-db`, `claudeforge-install`.
- **tmux** — `tmux-dev-group`, `tmux-restore`, `tmux-snapshot`, `tmux-osc52-copy`, `tmux-urls`, `tmux-resurrect-omp` (tmux-resurrect save hook: records each omp pane as `omp --resume <id>`, or `agentbox new <repos and -e options> -- omp --resume <id>` for a pane already running in a box, so a server restart brings the sessions back, not just the layout), `tmux-attention` (the ready-session queue and its cockpit pane: `push`/`drop` add or remove a session's line under `flock`, `next` swaps the next waiting pane into the cockpit and sends the current visitor home, bare `tmux-attention` runs the cockpit view, redrawing on `inotifywait`; every record names its tmux server's pid, so after a server restart nothing from the old server is swapped; bound to `C-b a` in `.tmux.conf`).
- **Monitoring / system** — `ephemeral-monitor`, `mem-usage`, `resource-warnings`, `fix-monitors`, `jj-agent-status`, `fix-watchman` (unwatches Watchman roots whose sync is broken, which otherwise adds ~60s to every jj command in that workspace), `legion-brief-watch` (daily, from the user timer `installers/legion-brief-watch.sh` arms: reads production Dispatch — nothing from GitHub — for the READY packets posted after the brief's release, and publishes once to Envoy role `agentc-1305` with `envoy notify` when none of the newest five is warned, the go-criterion for the brief's warn-first flip; a packet is warned when it carries `Warning: brief-missing`, carries the merger's no-brief placeholder `Outcome: (the pull request body carries no brief)`, or has no `Outcome:` line right after its READY header; the Dispatch URL and token resolve as every agent session's do, from `~/.config/opencode/envoy.json` unless `DISPATCH_URL`/`DISPATCH_TOKEN_FILE`/`DISPATCH_TOKEN` are set).
- **Version control** — `git-identity` (sets the git *and* jj commit identity for a repo together, so signing stays intact), `docs-pr-gate` (run by `shims/gh` on `gh pr create` in agent sessions: refuses a pull request to agent-c whose every file is documentation unless its head is today's `docs-batch/<topic>/<UTC date>` branch and no pull request from that branch has merged yet; documentation rides in the pull request that caused it or in that one batch per topic per day, AGENTC-847).
- **Secrets** (AGENTC-393) — `secret-run` (`secret-run [--reason R] [--wait DURATION] KEY... -- cmd` and `secret-run request [--reason R] KEY...`: the one command consumers and skills call for a secret; a process `agent-secrets identity` recognizes gets the secrets broker and its exit, never a fallback, and any other process gets `secrets` exactly as before; `identity` exists from the legion #1589 release on, so at the current pin every process gets secretsd), `agent-secrets-session` (`agent-secrets-session <agent argv…>`: the one registration step `shims/omp`, `cld` and `oc` exec their agent through — on a machine with the helper's unit it execs `agent-secrets register [--wait 10] --exec -- <argv>`, keeping the pid; anything else, or a helper that does not answer, runs the argv unregistered), `agent-secrets-login` (`agent-secrets-login <github-login>`: once per helper start, records the operator, starts the helper, waits for its socket and runs `agent-secrets launcher login`), `mcp-remote-from-env` (`npx -y -p mcp-remote@<version> mcp-remote-from-env <ENV_NAME> [mcp-remote args…]`: runs mcp-remote in-process with its server URL taken from `ENV_NAME`, which it then deletes, for a URL that is itself the credential; the home-assistant MCP launch uses it).
- **Misc** — `envoy`, `envoy-nats-seed` (prints the path of the per-boot 0600 cache of the `omp-session` NATS nkey seed, fetching it from Secrets Manager on the first launch after boot and refreshing it hourly in the background; `shims/omp`, `cld`, `oc` and `agentbox` export it as `NATS_NKEY_SEED_FILE`, and export nothing when it prints nothing; `--refresh` fetches now, after a rotation), `vendor-update` (rebases `vendor/*` clones), `mdview` / `mdview-server.py`, `joycon`, `brave-hw-encode`, `test-gh-routing`.

## Conventions

- Scripts are executable and self-contained; put a `#!` line and `set -euo pipefail` (bash) or the appropriate interpreter at the top.
- Match the naming and interpreter style of neighboring scripts.
- A secret never goes into a command's arguments: every user can read them from `/proc/<pid>/cmdline`, and any `ps` prints them. Pass it through the environment, a file, or stdin — curl's `--config` or `-H @file` on a `<(printf …)` path (`printf` is a builtin), mcp-remote's `${VAR}` header placeholders, `mcp-remote-from-env` for a URL.

## How changes take effect

This directory is on `PATH` (prepended in `.bashrc`), so scripts run by name in interactive shells. New scripts need the executable bit; no install step or symlink.
