# scripts

Standalone utility scripts and small tools.

## Contents

Executables covering several areas:

- **OpenCode/Claude/omp sessions** — `agentbox` (`new [-e NAME[=VALUE]]… <repo>… -- <cmd>|sh|ls|doctor|rebuild|restart`: one Sysbox box per agent session holding a fresh jj workspace of each `~/src/<repo>`, working in the first; `-e` sets a variable in the box, since the caller's environment does not reach it; `omp` inside it is the same `shims/omp`, run under `agentbox-run.ts` so `agentbox restart` can relaunch it in place on the current pin and plugins; the box dies with the session, and its workspaces and knives claims go with it), `agentbox-run.ts` (the box's main process: omp's parent, relaunches it on SIGUSR1 — `agentbox restart` inside a box — and otherwise exits with it), `oc`, `oco`, `omp-no-provider-keys` (the last hop of a default-profile launch in `shims/omp`, inside `agent-secrets register` and `mise x`: execs omp only when none of the provider keys `shims/omp` lists in `_keys` is in the environment omp would start with, nor assigned in a dotenv file omp loads into its own environment and every tool shell — `~/.env`, `~/.omp/.env`, the agent dir's `.env`, measured on 18.4.3 — and otherwise exits 1 naming each key and where it came from, never its value, so a key that would reach every tool subprocess fails the launch instead, AGENTC-1085. A `.env` in the working directory is not checked: omp filters it out of tool shells, so it cannot write a key into a transcript; `.env.local` reaches neither), `cld` (`cld [--profile NAME] [claude args…]`: Claude Code in the agent session environment; a profile is its own `CLAUDE_CONFIG_DIR` at `.claude-profiles/NAME`, so its own login), `claude-statusline` (Claude Code's status line, set in `.claude/settings.json`: a 10-cell bar of the context the next request carries, green under 50%, yellow under 80%, red above, e.g. `ctx ██▌░░░░░░░ 25% 250k/1M`, from the `context_window` Claude Code pipes in, prefixed with the profile name under `cld --profile`), `claude-session-repair.py`, `claude-transcript-times`, `sanitize-opencode-db`, `claudeforge-install`.
- **tmux** — `tmux-dev-group`, `tmux-restore`, `tmux-snapshot`, `tmux-osc52-copy`, `tmux-urls`, `tmux-resurrect-omp` (tmux-resurrect save hook: records each omp pane as `omp --resume <id>`, or `agentbox new <repos and -e options> -- omp --resume <id>` for a pane already running in a box, so a server restart brings the sessions back, not just the layout), `tmux-attention` (the ready-session queue and its cockpit pane: `push`/`drop` add or remove a session's line under `flock`, `next` swaps the next waiting pane into the cockpit and sends the current visitor home, bare `tmux-attention` runs the cockpit view, redrawing on `inotifywait`; every record names its tmux server's pid, so after a server restart nothing from the old server is swapped; bound to `C-b a` in `.tmux.conf`).
- **Monitoring / system** — `ephemeral-monitor`, `mem-usage`, `resource-warnings`, `fix-monitors`, `jj-agent-status`, `fix-watchman` (unwatches Watchman roots whose sync is broken, which otherwise adds ~60s to every jj command in that workspace), `advisor-report` (the AskGate and advisor metrics from session transcripts and `~/.omp/stats.db`, the labelling packet, the overlay kill writer, and the daily readout with the pre-registered kill and go rules; run by `omp/advisor-watch.timer`; messages the Envoy role `agentc-1305` prefixed `advisor-report (AGENTC-1323)`), `legion-brief-watch` (daily, from the user timer `installers/legion-brief-watch.sh` arms: reads production Dispatch — nothing from GitHub — for the READY packets posted after the brief's release, and publishes once to Envoy role `agentc-1305` with `envoy notify` when none of the newest five is warned, the go-criterion for the brief's warn-first flip; a packet is warned when it carries `Warning: brief-missing`, carries the merger's no-brief placeholder `Outcome: (the pull request body carries no brief)`, or has no `Outcome:` line right after its READY header; the Dispatch URL and token resolve as every agent session's do, from `~/.config/opencode/envoy.json` unless `DISPATCH_URL`/`DISPATCH_TOKEN_FILE`/`DISPATCH_TOKEN` are set).
- **Version control** — `git-identity` (sets the git *and* jj commit identity for a repo together, so signing stays intact), `docs-pr-gate` (run by `shims/gh` on `gh pr create` in agent sessions: refuses a pull request to agent-c whose every file is documentation unless its head is today's `docs-batch/<topic>/<UTC date>` branch and no pull request from that branch has merged yet; documentation rides in the pull request that caused it or in that one batch per topic per day, AGENTC-847), `canonical-untouched` (`canonical-untouched <checkout>...`: exits 1, listing each file, when a colocated jj checkout's files on disk differ from its working-copy commit, so a lane's stray write into `~/src/<repo>` is caught before it is snapshotted; it writes nothing, via `jj --ignore-working-copy` and `git --no-optional-locks`, and the lane rules have every lane run it before it yields).
- **Secrets** (AGENTC-393) — `secret-run` (`secret-run [--reason R] [--wait DURATION] KEY... -- cmd` and `secret-run request [--reason R] KEY...`: the one command consumers and skills call for a secret; a process `agent-secrets identity` recognizes gets the secrets broker and its exit, never a fallback, and any other process gets `secrets` exactly as before; until the helper holds a launcher credential, `identity` recognizes no host session, so every process gets secretsd), `agent-secrets-session` (`agent-secrets-session <agent argv…>`: the one registration step `shims/omp`, `cld` and `oc` exec their agent through — on a machine with the helper's unit it execs `agent-secrets register [--wait 10] --exec -- <argv>`, keeping the pid; anything else, or a helper that does not answer, runs the argv unregistered), `agent-secrets-login` (`agent-secrets-login <github-login>`: once per helper start, records the operator, starts the helper, waits for its socket and runs `agent-secrets launcher login`), `mcp-remote-from-env` (`npx -y -p mcp-remote@<version> mcp-remote-from-env <ENV_NAME> [mcp-remote args…]`: runs mcp-remote in-process with its server URL taken from `ENV_NAME`, which it then deletes, for a URL that is itself the credential, and replaces the URL and its last path segment with `<ENV_NAME>` in everything written to stderr, where mcp-remote logs the URL; the home-assistant MCP launch uses it).
- **Model access** — `hawk-token` (prints one Hawk access token on stdout and nothing else, for the `apiKey: "!hawk-token"` providers listed in `omp/AGENTS.md`. omp kills a `!command` after 10 s, so the whole run spends a single 9 s budget, and a mint that printed nothing was worse than one that failed: omp stores the empty value as the anthropic apiKey, reports MissingApiKeyError, makes no request, and its own re-mint-on-401 cannot fire again that turn — one transient overrun killed four agent lanes on 2026-09-30, and a mint that takes ~1.5 s idle takes 7-9 s at load 200 on 32 cores. It mints from a private shallow agent-c checkout it owns under `~/src/.hawk-token`, never `~/src/agent-c`, through two slots and an atomically renamed `current` symlink, so a detached background refresh killed at any point leaves the live slot and minting untouched; refresh output goes to `refresh.log` beside them. Every successful mint rewrites `last-good-token` there (0600, the token alone, renamed into place so a concurrent reader sees one token or the other), and a run where no mint finished inside the budget serves that token instead of nothing — but only while its `exp` is at least 5 minutes away, and only for the no-argument form, since an argument reaches the mint and can ask for a different token. An expired, malformed, empty or absent cache fails loudly with the reason and prints nothing: serving an expired token is worse than failing, and empty stdout with exit 0 is the defect the cache exists to prevent. A token is reusable across processes until it expires — measured against middleman's `/openai/v1/models`, one jti got 200 from three separate processes while the same token with one character altered got 401 — so a never-seen jti is a property of minting fresh, not a requirement of the gateway.)
- **Misc** — `envoy`, `envoy-nats-seed` (prints the path of the per-boot 0600 cache of the `omp-session` NATS nkey seed, fetching it from Secrets Manager on the first launch after boot and refreshing it hourly in the background; `shims/omp`, `cld`, `oc` and `agentbox` export it as `NATS_NKEY_SEED_FILE`, and export nothing when it prints nothing; `--refresh` fetches now, after a rotation), `vendor-update` (rebases `vendor/*` clones), `mdview` / `mdview-server.py`, `joycon`, `brave-hw-encode`, `test-gh-routing`.

## Conventions

- Scripts are executable and self-contained; put a `#!` line and `set -euo pipefail` (bash) or the appropriate interpreter at the top.
- Import-only shared Python modules here are libraries: they may omit the `#!` line and the executable bit; an executable entrypoint keeps both.
- Match the naming and interpreter style of neighboring scripts.
- A secret never goes into a command's arguments: every user can read them from `/proc/<pid>/cmdline`, and any `ps` prints them. Pass it through the environment, a file, or stdin — curl's `--config` or `-H @file` on a `<(printf …)` path (`printf` is a builtin), mcp-remote's `${VAR}` header placeholders, `mcp-remote-from-env` for a URL.

## How changes take effect

This directory is on `PATH` (prepended in `.bashrc`), so scripts run by name in interactive shells. A new entrypoint needs the executable bit; an import-only library does not. No install step or symlink either way.
