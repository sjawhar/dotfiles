# scripts

Standalone utility scripts and small tools.

## Contents

Executables covering several areas:

- **Claude/omp sessions** — `agentbox` (`new [-e NAME[=VALUE]]… <repo>… -- <cmd>|sh|ls|doctor|rebuild|restart`: one Sysbox box per agent session holding a git clone of its own of each `~/src/<repo>`, working in the first; `-e` sets a variable in the box, since the caller's environment does not reach it; `omp` inside it is the same `shims/omp`, run under `agentbox-run.ts` so `agentbox restart` can relaunch it in place on the current pin and plugins; the box dies with the session, and its clones, unless one holds unpushed work, and its knives claims go with it), `agentbox-run.ts` (the box's main process: omp's parent, relaunches it on SIGUSR1 — `agentbox restart` inside a box — with the launch's configuration flags and none of its messages, and otherwise exits with it), `agent-session` (`agent-session <agent> [args…]`: the session environment `shims/omp` and `cld` exec their agent through — the gh-app routing include, added once; this checkout's `shims/` first on `PATH`; then the first `<agent>` on `PATH` that is not a wrapper (mise's shims dir, or a file whose real path is in a `shims/` dir), exec'd through `agent-secrets-session`, or exit 127 when there is none), `cld` (`cld [--profile NAME] [claude args…]`: Claude Code in the agent session environment; the default profile reaches Anthropic through the Hawk gateway: it passes claude `--settings` with `apiKeyHelper` set to `hawk-token`, which Claude Code re-runs at start, every five minutes and on a 401, each run a fresh mint, and `ANTHROPIC_BASE_URL` set to middleman; a profile is its own `CLAUDE_CONFIG_DIR` at `.claude-profiles/NAME`, so its own login and no gateway route), `claude-statusline` (Claude Code's status line, set in `.claude/settings.json`: a 10-cell bar of the context the next request carries, green under 50%, yellow under 80%, red above, e.g. `ctx ██▌░░░░░░░ 25% 250k/1M`, from the `context_window` Claude Code pipes in, prefixed with the profile name under `cld --profile`), `claude-session-repair.py`, `claude-transcript-times`, `claudeforge-install`.
- **omp session recovery** — `omp-session-slim` (`omp-session-slim [--apply] SESSION.jsonl…`: shrinks a session file the `proactive_memory` experiment (`omp/extensions/experiments/`) bloated past JavaScriptCore's 2 GiB maximum string length. That feature appended a full copy of its knowledge bank to the session on every change, so in a long session thousands of >1 MB snapshots pile up and omp can no longer resume it: it crashes in `createSessionManager` with `RangeError: Out of memory` while building the whole file as one string (AGENTC-1794 the omp-side OOM, AGENTC-1941 the feature itself, now gated off). Only the newest bank snapshot on each branch leaf is ever read back (`loadState` in `proactive-memory-core.ts`), so it keeps those and replaces every superseded snapshot's `data` with a tiny valid-empty marker, leaving its id/parentId/timestamp and every non-bank line byte-identical so the entry tree and all cross-references stay intact. Dry-run by default; `--apply` rewrites in place after writing a zstd backup under `~/.omp/agent/sessions-slim-backups/`, and it refuses a session a live omp process still holds open. Run it only on a stopped session).
- **omp session forks** — `omp-fork` (`omp-fork [--at ENTRY] [--model M] [--max-time T] [--cwd DIR] [--keep DIR] SESSION.jsonl (PROMPT | --prompt-file FILE)`: asks a read-only copy of an omp session one question and prints `{text, model, fallback, cost, tokens, cut, fork_session}` as JSON. The copy goes into a private scratch directory and is resumed for one `omp -p --mode json` turn, in the session's own working directory and on its own model; the original is never written. `--at` cuts the copy after that line of the file, moved back to the last message with no tool call still waiting for its result, so the fork answers as the agent stood then. The fork runs with Envoy off, because a resumed copy otherwise re-registers under the live session's id, takes its messages and roles, and on exit drops the live session's registration until its next heartbeat; the Dispatch section is kept for reads. `fallback` is true when an answer came from another model than the session's own. Telling the fork not to change anything is the prompt's job.)
- **tmux** — `tmux-dev-group`, `tmux-restore`, `tmux-snapshot` (`tmux-snapshot` saves the current tmux session's windows, panes and each omp pane's session, found the way `tmux-resurrect-omp` finds it, to `~/.dotfiles/.tmux-workspace/`; `tmux-restore [--dry-run] [SNAPSHOT]` recreates them and resumes each session with the recorded `omp --resume <id>` or `agentbox new <spec> -- omp --resume <id>`), `tmux-osc52-copy`, `tmux-urls`, `tmux-resurrect-omp` (tmux-resurrect save hook: records each omp pane as `omp --resume <id>`, or `agentbox new <repos and -e options> -- omp --resume <id>` for a pane already running in a box, so a server restart brings the sessions back, not just the layout), `tmux-attention` (the ready-session queue and its cockpit pane: `push`/`drop` add or remove a session's line under `flock`, `next` swaps the next waiting pane into the cockpit and sends the current visitor home, bare `tmux-attention` runs the cockpit view, redrawing on `inotifywait`; every record names its tmux server's pid, so after a server restart nothing from the old server is swapped; bound to `C-b a` in `.tmux.conf`).
- **Monitoring / system** — `ephemeral-monitor`, `mem-usage`, `resource-warnings`, `fix-monitors`, `jj-agent-status`, `fix-watchman` (unwatches Watchman roots whose sync is broken, which otherwise adds ~60s to every jj command in that workspace).
- **Version control** — `git-identity` (sets the git *and* jj commit identity for a repo together, so signing stays intact), `docs-pr-gate` (run by `shims/gh` on `gh pr create` in agent sessions: refuses a pull request to agent-c whose every file is documentation unless its head is today's `docs-batch/<topic>/<UTC date>` branch and no pull request from that branch has merged yet; documentation rides in the pull request that caused it or in that one batch per topic per day, AGENTC-847), `canonical-untouched` (`canonical-untouched <checkout>...`: exits 1, listing each file, when a checkout's files on disk differ from the commit it is on (a colocated jj checkout's working-copy commit, a plain git checkout's HEAD), or when a jj working-copy commit is not empty, which is where a lane's stray write into `~/src/<repo>` ends up once a snapshot has run there, as sessions do every few minutes; it writes nothing, via `jj --ignore-working-copy` and `git --no-optional-locks`, and the lane rules have every lane run it before it yields).
- **PR review gates and merge** — `pr-gate run`, `pr-gate check` and `pr-gate merge` (dispatched by `pr-gate` to `pr-gate-lane`), the one command every lane uses to run a gate and to merge. `pr-gate run --repo O/R --pr N --gate NAME --brief FILE [--model M] [--out DIR] [--cwd DIR] [--legion-checkout DIR] [--since SHA]` reads the head, runs `omp -p --mode json` on the brief with the head prepended (default `anthropic/claude-opus-5-5:xhigh`; any provider, `openai/gpt-6-astra:xhigh` for a cross-model gate, except that a `theorem-labs/*-hdo` repo refuses every non-`anthropic/` model, since HDO material never reaches a non-Claude agent; the repo name is the guard, the brief is not scanned), with no deadline of its own, so callers run it as a background job with bash `timeout: 0`. It posts nothing and exits 2 on a provider error or refusal, 3 when any message ran on another provider or model, 4 when the final message's first line is not `VERDICT: APPROVE|REQUEST_CHANGES`, 6 when a non-Claude run left its HDO-free checkout (below); otherwise it posts one comment headed `**Gate: <name> at <head>** — <verdict>` with model, provider and the review, plus a `<!-- pr-gate gate= head= verdict= model= -->` marker, and reads it back. When the head moved during the run it still posts, with the reviewed sha in the heading and the marker and ` (head has since moved to <sha>; not valid for merge)` after the verdict, then exits 5; `check` and `merge` refuse that comment, since it names an older head. `--since SHA` makes the run a delta review: it prepends `Review only the delta <since>..<head>, which follows a reviewed head` and the delta's file list (from GitHub's compare) to the brief, so the run after a moved head reviews only what changed. HDO-derived material inside other repositories is held off the same way. `pr-gate-hdo-paths` lists it as `<owner>/<repo>:<glob>` lines, repo-relative (BET's PEE screen, PEE capture source and replays; Sami rules on what belongs, BET's task-pipeline lane names the paths), and each machine's untracked `~/.config/pr-gate/hdo-paths.local` (or `PR_GATE_HDO_LOCAL`) adds its absolute paths in the same form, such as lane checkouts and run outputs. For a non-`anthropic/` model on a listed repo, `run` refuses with one line naming the first match when the file is missing, when any of the PR's changed files (all pages of GitHub's PR files API, refused if fewer than `changed_files` come back) match, or when a caller's `--cwd` sits under a local path or holds a matching path on disk or in any commit of a git repository in it. Otherwise it builds `OUT/checkout`, the PR head with no `.git` and the listed paths never fetched (a depth-1 blob-less fetch of `refs/pull/N/head` into a throwaway git dir, sparse-checked-out without them; `PR_GATE_GIT_URL` overrides the remote for tests), runs omp there with `--cwd` and only the `read,bash,grep,glob,find,ast_grep` tools, and before posting scans `events.jsonl`: a session cwd other than the checkout, any other tool (a subagent's reads never reach the parent's events), an internal URI other than `skill://`, `rule://`, `omp://` or the web, a read or bash path outside the checkout and `OUT/tmp`, `~`/`$HOME`, or a listed path named anywhere exits 6 with nothing posted. This is a cooperative guard on a run that follows its brief, not a sandbox: it reads the logged tool arguments and does not follow `cd`, variables or what a command reads on its own, so a run that sets out to escape can. The comment carries no dollar figure: the run's summed cost goes only to stdout and `OUT/summary.json`, for the ledger. For sjawhar/legion it first runs that checkout's `.github/scripts/check-private-names.sh` on the body (`--legion-checkout` or `PR_GATE_LEGION_CHECKOUT`, refused when missing). `pr-gate check --repo O/R --pr N [--head SHA] (--require G[,G…] | --require-any) [--allow-no-checks]` runs merge's checks and merges nothing: it exits 0, or 1 with the refusal lines merge prints. They are: the PR heads at `--head` when given; the newest run of every check (by workflow and name) is SUCCESS, SKIPPED or NEUTRAL, and at least one check exists (or `--allow-no-checks`); with `--require`, each named gate's newest marker comment names this head with APPROVE; with `--require-any`, at least one gate's newest marker comment does, and no gate's newest marker comment at this head is REQUEST_CHANGES. It reads a merged PR too. `pr-gate merge --repo O/R --pr N --require G[,G…] [--allow-no-checks] [--approve-script PATH]` runs the same checks on an open PR, then runs `gh pr merge --squash --match-head-commit <head>` (never `--auto`), or `--approve-script <pr> <head> <body-file> <subject>` with a body listing the gate comment URLs, both with `PR_GATE_MERGE=1` (the variable `shims/gh`'s merge guard, `gh-merge-guard`, lets through), and prints the merge commit. `gh-merge-guard` is that guard: in an agent session `shims/gh` runs it on `gh pr merge`, `gh pr review` and `gh api` calls, and it refuses a merge or approval of a sjawhar/legion or theorem-labs/agent-infra pull request (`shims/AGENTS.md`). Tests: `tests/test_pr_gate_lane.py` (with the review-App approve script on the machine that holds it), `tests/test_gh_merge_guard.py`.

- **Model access** — `hawk-token` (prints one Hawk access token on stdout and nothing else; no longer what omp's `apiKey` points at directly — see `hawk-token-fast` below. omp kills a `!command` after 10 s, so the whole run spends a single 9 s budget, and a mint that printed nothing was worse than one that failed: omp stores the empty value as the anthropic apiKey, reports MissingApiKeyError, makes no request, and its own re-mint-on-401 cannot fire again that turn — one transient overrun killed four agent lanes on 2026-09-30, and a mint that takes ~1.5 s idle takes 7-9 s at load 200 on 32 cores; reproduced 2026-10-04 with 64 added `stress-ng` CPU hogs on top of this box's ambient 30-45 load: a mint that normally finishes in ~3 s took 10.1 s wall clock. It mints from a private shallow agent-c checkout it owns under `~/src/.hawk-token`, never `~/src/agent-c`, through two slots and an atomically renamed `current` symlink, so a detached background refresh killed at any point leaves the live slot and minting untouched; refresh output goes to `refresh.log` beside them. Every successful mint rewrites `last-good-token` there (0600, the token alone, renamed into place so a concurrent reader sees one token or the other), and a run where no mint finished inside the budget serves that token instead of nothing — but only while its `exp` is at least 5 minutes away, and only for the no-argument form, since an argument reaches the mint and can ask for a different token. An expired, malformed, empty or absent cache fails loudly with the reason and prints nothing: serving an expired token is worse than failing, and empty stdout with exit 0 is the defect the cache exists to prevent. A token is reusable across processes until it expires — measured against middleman's `/openai/v1/models`, one jti got 200 from three separate processes while the same token with one character altered got 401 — so a never-seen jti is a property of minting fresh, not a requirement of the gateway), `hawk-token-fast` (what `apiKey: "!hawk-token-fast"` providers in `omp/AGENTS.md` actually call: reads `last-good-token` and prints it with no network call, no git, no uv, and no OAuth exchange — one stat, one read, one regex match, so it cannot itself blow any budget regardless of system load. Falls back to a live `hawk-token` mint, with its full cache-fallback behavior, only when the cache is missing, malformed, or under the 5-minute floor — the cold-start or refresher-outage case. `installers/hawk-token-refresh.sh` arms the `hawk-token-refresh` user timer (`omp/hawk-token-refresh.{service,timer}`) that runs plain `hawk-token` every 3 minutes with no budget of its own, keeping the cache inside its floor with about 55 minutes of slack even if every refresh in a row fails.)

## Conventions

- Scripts are executable and self-contained; put a `#!` line and `set -euo pipefail` (bash) or the appropriate interpreter at the top.
- Import-only shared Python modules here are libraries: they may omit the `#!` line and the executable bit; an executable entrypoint keeps both.
- Match the naming and interpreter style of neighboring scripts.
- A secret never goes into a command's arguments: every user can read them from `/proc/<pid>/cmdline`, and any `ps` prints them. Pass it through the environment, a file, or stdin — curl's `--config` or `-H @file` on a `<(printf …)` path (`printf` is a builtin), mcp-remote's `${VAR}` header placeholders, `mcp-remote-from-env` for a URL.

## How changes take effect

This directory is on `PATH` (prepended in `.bashrc`), so scripts run by name in interactive shells. A new entrypoint needs the executable bit; an import-only library does not. No install step or symlink either way.
