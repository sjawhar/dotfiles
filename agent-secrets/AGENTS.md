# agent-secrets

The host side of agent secrets (AGENTC-393): the user unit and wrapper for `agent-secrets-helper`, the daemon that pins each host agent session by pidfd, keeps its broker key in memory, enrolls it as `kind: host`, and signs its proofs. Agent boxes do not use it: a box has its own key under its private runtime dir (`scripts/agentbox`, `agentbox/AGENTS.md`).

- `agent-secrets-helper.service` — `ExecStart` is the wrapper; `AGENT_SECRETS_URL` names the production broker, `~/.config/agent-secrets/env.local` (optional, uncommitted) overrides it.
- `agent-secrets-helper` — `mise exec agent-secrets -- agent-secrets-helper serve`; the binary comes from `mise.toml` `[tools.agent-secrets]` (sjawhar/legion `cmd/agent-secrets-helper`).
- `installers/agent-secrets.sh` links and enables the unit, and restarts it only when the pinned version or the unit changed — never while `agent-secrets-helper sessions` lists a session, unless `AGENT_SECRETS_HELPER_RESTART_WITH_SESSIONS=1`, because a restart re-pins live sessions with fresh keys and their grants are revoked.
- Once per helper start (the credential lives only in the helper's memory, so a restart or reboot clears it): `agent-secrets-login <github-login>` writes `~/.config/agent-secrets/operator` (0600; never mounted into a box), starts the helper, and runs `agent-secrets launcher login` — a socket call the helper answers from memory; nothing credential-shaped ever touches disk. `agent-secrets launcher login-status` is the side-effect-free liveness probe (exit 0 only when a credential is currently issued).
- A host session becomes a session root when its launcher runs `agent-secrets register [--wait 10] --exec -- <agent argv>` (`shims/omp`, `scripts/oc`, `scripts/cld`); every process under it gets proofs from the socket `$XDG_RUNTIME_DIR/agent-secrets/helper.sock` through `AGENT_SECRETS_HELPER_SOCK`; when the root exits the helper revokes the enrollment. `--wait 10` holds the launch until the session is enrolled, and the launchers pass it only while `launcher login-status` exits 0: without a credential the helper cannot enroll anyone, and the wait would add 10 s to every launch.
- `scripts/agentbox new` enrolls a box only while the helper holds a live credential; otherwise the box starts with no key and no `enrollment.pending`, says so on stderr, and its agents use secretsd.
