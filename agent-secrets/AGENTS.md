# agent-secrets

The host side of agent secrets (AGENTC-393): the user unit and wrapper for `agent-secrets-helper`, the daemon that holds the operator's launcher credential in memory, pins each host agent session by pidfd, keeps its broker key in memory, enrolls it as `kind: host`, and signs its proofs. Agent boxes have their own key under their private runtime dir, but the helper is how the host enrolls and unenrolls each box (`scripts/agentbox`, `agentbox/AGENTS.md`). Sami's own shells never depend on it: they use secretsd (`scripts/secret-run`).

- `broker.env` — the production broker's URL, written once: the unit reads it (`EnvironmentFile`), and `scripts/agent-secrets-session`, `scripts/secret-run`, `scripts/agent-secrets-login`, `scripts/agentbox` and `.bashrc` source it when `AGENT_SECRETS_URL` is unset. `~/.config/agent-secrets/env.local` (optional, uncommitted) overrides it for the helper.
- `agent-secrets-helper.service` — `ExecStart` is the wrapper. `Restart=always`: a SIGTERM from anything but systemd (a `pkill -f "agent-secrets-helper serve"` meant for a test rig's helper matches this one) ends the helper with exit 0, which `on-failure` never restarted, so systemd restarts it after any exit except its own stop. The restarted helper holds no launcher credential until the next `agent-secrets-login`.
- `agent-secrets-helper` — `mise exec agent-secrets -- agent-secrets-helper serve`; the binary comes from `mise.toml` `[tools.agent-secrets]` (sjawhar/legion `cmd/agent-secrets-helper`, its asset digests pinned).
- `installers/agent-secrets.sh` — a devbox role installer (`devbox/install.sh`; the root `install.sh` does not run it, so the laptop has no helper). It links and enables the unit, and restarts it only when the pinned version, the unit, the wrapper or `broker.env` changed — never while `agent-secrets-helper sessions` lists a session, unless `AGENT_SECRETS_HELPER_RESTART_WITH_SESSIONS=1`, because a restart re-pins live sessions with fresh keys and their grants are revoked.
- Once per helper start (the credential lives only in the helper's memory, so a restart or reboot clears it): `agent-secrets-login <email>`, naming the operator by the email they sign in to Dispatch with (anything else is refused), writes it lowercased to `~/.config/agent-secrets/operator` (0600; never mounted into a box), starts the helper, waits for its socket, and runs `agent-secrets launcher login` — a socket call the helper answers from memory; nothing credential-shaped ever touches disk. `agent-secrets launcher login-status` is the side-effect-free probe: it prints the login state (`none`, `pending`, `denied`, `expired`, `issued`) and exits 0 only on `issued`. It prints `issued` whenever the helper holds a live launcher credential, even when a newer re-login was denied, expired unapproved or is still pending (stderr names that login and its code), and `expired` once the broker refuses the held credential.
- A host session becomes a session root when its launcher (`shims/omp`, `scripts/cld`, `scripts/oc`) execs the agent through `scripts/agent-secrets-session`, which runs `agent-secrets register [--wait 10] --exec -- <agent argv>`; every process under it gets proofs from the socket `$XDG_RUNTIME_DIR/agent-secrets/helper.sock` through `AGENT_SECRETS_HELPER_SOCK`, and when the root exits the helper revokes the enrollment. `--wait 10` holds the launch until the session is enrolled and is passed only while `login-status` says `issued`; a helper that does not answer means no registration at all, so a stopped helper costs a launch nothing. Why registering without a credential is safe: the comment at the top of `scripts/agent-secrets-session`.
- `scripts/agentbox new` enrolls a box only while the helper holds a live credential; otherwise the box starts with no key and no `enrollment.pending`, says so on stderr, and its agents use secretsd. A box whose enrollment fails loses its key the same way.
