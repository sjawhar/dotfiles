# The systemd user timers that must be enabled and running on this box.
#
# A linked .service with no linked .timer does not fire and is absent from
# `systemctl --user list-timers`. This list lets the box say which timers are missing.
#
# Two things read this file:
#   - scripts/unit-health-watch, every 5 minutes. It alerts when a timer named here is missing
#     from this user manager, is not enabled, or has not fired for more than three times its
#     own interval.
#   - installers/expected-timers.sh. It links and `enable --now`s every timer named here, which
#     is idempotent: run it as often as you like, and after every reset of the box.
#
# How to add one: one timer name per line, with a comment saying who owns it. A name with no
# `.timer` suffix gets one. `#` starts a comment anywhere in a line. Blank lines are ignored.
# The unit files may live in ~/.dotfiles/omp/ or ~/.dotfiles/devbox/ (the installer links them
# from there) or only in ~/.config/systemd/user (the installer enables what it finds and says
# so). Nothing here names an absolute path.
#
# After the name a line may carry `key=value` fields. A value runs to the next `key=` or to
# the end of the line, so a value may hold spaces. Two keys are read:
#
#   owner=<who>     Who the alert names. The comment after `#` may say it instead; the field
#                   is what goes into the message.
#   max_run=<span>  How long one run of this timer's service may take before unit-health-watch
#                   says RUN NEVER ENDS: `3h`, `45m`, `90s`. Without it the watch uses its own
#                   limit (two periods, or twice the unit's p99 run time), which knows nothing
#                   about what the unit does. Only the unit's owner should set it.
#
# Removing a name is how you retire a timer: disable it, then delete its line. A name left here
# for a timer nobody wants makes an alert every 5 minutes.
