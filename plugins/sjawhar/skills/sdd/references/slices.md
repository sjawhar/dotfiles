# Slices

- Each slice merges as one PR.
- Each slice ends in something the requester can try: a command that runs, a page that renders, a real record that moves.
- Cut thin end-to-end paths, not layers.
- Ship the first usable thin end-to-end path first.
- **A slice is a merge and acceptance boundary, not a work assignment:**
  - its tasks still split;
  - independent slices run at once.
- Later slices extend the contracts named up front.
- A slice that needs scaffolding you would later delete merges with the next.
