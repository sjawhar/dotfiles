# Slice classes, and what proves each

| Class | Proven by |
| --- | --- |
| Platform or application | The application's own surface |
| Infrastructure | What the repo's own instructions name |
| Task authoring (evaluation tasks, other content the repo ships) | Running the task |
| Task queueing (content through a submission or QA queue) | The state the queue records per item |

- Take each class's commands, driver, acceptance and PR template from the repo's guides, skills and CI; this skill supplies none.
- Work that crosses classes exercises each boundary and the join.
- A repo template asking for another class's checks: follow the change's class and name the mismatch in the plan.
- No documented workflow: prove it through its consumer's surface (`opening-a-pr`).
