# Presenting the run to Sami

Read this before you write the message that carries the report, and before you ask him to decide anything.

- Lead with the window's counts and the failure types, not with what the run did. He reads the first screen.
- Present at most 3 decisions per message. Give each as: current state, what the evidence says, the options with their trade-offs, your recommendation. Name what is queued behind them, and bring the next one as each resolves.
- Never end with a numbered menu of every open decision: a menu moves the sorting work to him.
- Explain each decision in the message itself. A label plus a section reference ("§D, 9 items") is not a decision, and one that needs the report open beside it is not ready.
- Present rule proposals one at a time, each with why the cheaper homes (a tool, a default, the skill loaded at that step) do not fit.
- Define every analysis term in the sentence that uses it: reader names, type names, record ids.
- Never use a count as an argument without one concrete example beside it: a rate with no exchange behind it is what he calls generic.
- Write plain English: short sentences, one idea each, the words the code and he already use.
- Quote his words only as evidence of a finding, never back at him as framing.
