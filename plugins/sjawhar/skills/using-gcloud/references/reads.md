# Which identity reads what

Route 1 of `SKILL.md`, "A permission error": a read, never with a person's key, with `GCLOUD_READER_REASON` (`AZ_READER_REASON` for Azure) set to the issue key and each object read.

- Google metadata, IAM policies, a bucket's object list, metric time series, quotas and billing accounts: read as `legion-reader@` (`gcloud-reader --as legion -- gcloud ...`). `metadata-reader@`'s roles sit on folder `theorem`, which holds no project until the projects move into it; once that move's apply record reads `applied:` and a read through `METADATA_READ` answers for `theorem-agent-infra`, plain `gcloud-reader <gcloud args>` is the route again.
- The organization's IAM policy and policies, the IAM policy search, Admin Activity logs, `agent_spend` rows, insights, Policy Troubleshooter and Support cases: `gcloud-reader --as legion -- <command>`, as `legion-reader@` (`bq` and `sh -c` work too).
- Who holds a role or a permission where, and whether one principal holds it: never `gcloud asset analyze-iam-policy` (Policy Analyzer). Google requires `cloudasset.assets.searchAllResources` for it, and no reader holds that permission, because the resource search returns a Cloud Run service's environment values. Run these two through `gcloud-reader --as legion --` instead:
  - Who holds it: `gcloud asset search-all-iam-policies --scope=organizations/<org> --query='policy.role.permissions:<permission> AND (resource=<full resource name> OR resource=//cloudresourcemanager.googleapis.com/projects/<project> OR resource=//cloudresourcemanager.googleapis.com/organizations/<org>)'`, where `gcloud organizations list` gives `<org>`, with one more `resource=//cloudresourcemanager.googleapis.com/folders/<id>` term for each folder that `gcloud projects get-ancestors <project>` lists. The answer is candidate bindings, not an access decision: the search does not expand a group, does not evaluate a binding's condition (a condition you cannot evaluate leaves that access unknown), and reads no deny policy. A `projectOwner:`, `projectEditor:` or `projectViewer:<project>` member stands for that basic role's holders on the project: list them with the same search on the project alone, filtered to `roles/owner`, `roles/editor` and `roles/viewer`. To find who can act as a service account that an answer names, search again on that account and its ancestors with `policy.role.permissions:(iam.serviceAccounts.actAs OR iam.serviceAccounts.getAccessToken OR iam.serviceAccounts.getOpenIdToken OR iam.serviceAccounts.implicitDelegation OR iam.serviceAccounts.signBlob OR iam.serviceAccounts.signJwt)`, and again for each new service account, until an answer names no new one.
  - Whether one principal holds it: `gcloud policy-intelligence troubleshoot-policy iam <full resource name> --principal-email=<principal> --permission=<permission>`. For a bucket or a BigQuery dataset it exits 1, because the reader cannot read that resource's own policy: use the search there.
  - The search does not see a managed folder's policy, and neither reader reads one until the projects move into the folder of the first bullet: record that folder's readers as unknown, with that reason.
  agent-infra's `legion/references/reads.md`, "Who holds a permission, and whether one principal holds it", gives the measured answers.
- Azure resources: `az-reader <az args>`, as the Azure identity `legion-reader`.
- The tailnet's devices (`devices`) or policy file (`acl`): agent-infra's `legion/checks/tailnet-read.sh`, run from a file, never from `<(...)`:
  `f=$(mktemp) && gh api 'repos/theorem-labs/agent-infra/contents/legion/checks/tailnet-read.sh?ref=main' -H 'Accept: application/vnd.github.raw' >"$f" && secret-run --register --ttl 15m --reason '<key>: the device list of the tailnet' TAILSCALE_READ -- bash "$f" devices; rm -f "$f"`
- Container logs of `theorem-agent-infra`, the daemons' included: the box identity, `dev-sjawhar@`, until this box moves to `dev-box@`; after that, a need is a missing grant, reported on your issue.
- A read none of these makes is a missing grant: report the call and the refusal on your issue, and take no other identity.
