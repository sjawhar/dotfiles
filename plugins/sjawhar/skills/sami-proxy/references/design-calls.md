# Design calls Sami has made

Read this when the question is a design, architecture or cleanup call. The `pNNNNN` ids are entries in `experiments/sami-proxy/precedents.md` in the private `sjawhar/agent-eval-data` repo; cite only ids you read.

- Build complete slices that a person can use and test, with their wiring and feedback, even across packages. An explicitly smaller goal can still be complete. Simplicity never cuts requested scope (p05665, p06035, p06055, p06244, p06139).
- Simplify the structure, not only the diff. Delete duplicate paths and fix the dependency mess instead of wrapping it, because a shared helper is not unification while two mechanisms remain (p07570, p12885, p18297). Two distinct concerns may both stay: "one product" does not require banning a useful native tool or replacing its storage (p12748, p13854).
- Research existing config, APIs, packaging, release tooling, identities and primitives before you write a workaround. "Add this feature" does not mean "advance everything else" (p12349, p18741). A generic process skill does not hardcode one project (p22192).
- Use resource config, not branches on environment names (p09708), and identity, not checkout location (p21613). Add no knob to keep a distinction that should disappear (p07570). "Config over code" is a preference, not a universal answer.
- Fix the producer, not every consumer (p16206, p19705). Delete manual duplication that drifts. Use data ranges and clear labels, not formulas that need an edit for each new row (p05728). A build failure must not become a silent runtime fix; a temporary fix that unblocks a person is allowed only while the source fix is under way.
- Before you report a metric, state what it measures: harness failure is not model resistance, and nominal concurrency is not throughput (p06084, p08075, p12949). Instrument and shorten the experiment before another blind run (p12628). A green result that dropped the measured behavior is not proof.
- Before approval, build and run the changed path with the relevant permissions, providers, modes and current code (p13662, p18522, p20075, p20879). Adding more names for the same check does not add verification; run the check (p16899).
- A safeguard must answer a real need: no invented deploy scenarios, extra checks or new access systems as "hardening" (p10051). User-level tooling needs no organization-wide authority (p09345). Tighter deploy permissions keep a way to test full changes independently (p17174).
- A clean cutover is the default when the consumers can migrate (p05680, p09345), and it is never a license to lose work. Run a new path in parallel with the old one without using its result (shadowing) only when someone asks or you can name the failure it would catch, not as a ritual (p17928). The proxy itself only predicts; its verdict never acts on Sami's behalf, and no precedent overrides that.
- Preferences change, so check the latest word before you apply an old one. A decoupling request can end in combined systems once their roles are clear (p17577, p17578); an early judging design lost to a later one (p15779, p17922); no past implementation is a permanent rule. Cache freshness needs evidence: never assume "closed forever" (p19504).
