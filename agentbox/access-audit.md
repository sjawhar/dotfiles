## Observed host state

The audit read both deployed source trees and representative existing boxes.
Both hosts used `sysbox-runc`, private IPC, default PID namespaces, a writable container root, and no custom `CapAdd`, `CapDrop`, or `SecurityOpt`.
Both boxes bound their own host's `.config/gcloud` writable.
They had read-only config and gateway binds and no whole-user NVMe bind.
The durable user tree was already writable on both hosts.

`gcloud config configurations list` and `gcloud auth list` showed:

- `sami-devbox`: `box` active as `dev-sjawhar@theorem-agent-infra.iam.gserviceaccount.com`, empty `default`, no `theorem` config or Sami account.
- `sami-rocqperf`: the same active `box`, empty `default`, inactive `theorem` as `sami@theorem.dev`, and both accounts stored.

The entrypoint does not filter gcloud accounts. The missing devbox user login is host state.
This change copies no user credential between machines.

## Acceptance ownership

BoxAccess runs the integrated unit suite and new-box acceptance once, after installation.
The required new-box checks cover both disks, shared configuration writes, SSH access, Docker state, skill parity, and canonical Envoy registration.
Running sessions are not restarted. They receive changed mounts and identity on their next re-box.
